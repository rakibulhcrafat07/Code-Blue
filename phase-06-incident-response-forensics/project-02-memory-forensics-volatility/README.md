# Project 2 — Memory Forensics with Volatility

**Phase:** [6 — Incident Response & Forensics](../)
**Status:** ⬜ To Do

## Objective

Learn to pull evidence out of a RAM capture — processes, network connections, injected code — that disk forensics alone would miss.

## Tasks

- [ ] Install Volatility3
- [ ] Capture RAM from the lab VM (or use a public sample memory image, e.g. from CyberDefenders)
- [ ] Identify the OS profile / build info for the image
- [ ] List running processes and flag anything unexpected
- [ ] Check network connections active at capture time
- [ ] Look for process injection or hidden/unlinked processes
- [ ] Extract and note any suspicious strings or artifacts

## Tools

Volatility3, a memory image (self-captured or a public DFIR sample set)

## Deliverable

A short findings write-up: what was running, what looked wrong, and what the memory image alone tells you about the incident.
