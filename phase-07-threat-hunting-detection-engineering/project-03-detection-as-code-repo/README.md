# Project 3 — Detection-as-Code Repo

**Phase:** [7 — Threat Hunting & Detection Engineering](../)
**Status:** ⬜ To Do

## Objective

Treat your detection rules like software: version-controlled, documented, and reviewable — not living only inside a SIEM's UI.

## Tasks

- [ ] Create a `detections/` folder (in this repo or a separate one) to hold rule definitions as text/YAML/JSON files
- [ ] Move at least 5 of your existing rules (from Phases 4, 5, and 7) into that folder
- [ ] Add a short metadata header to each: MITRE technique, purpose, false-positive notes
- [ ] Write a simple script that checks each file has the required metadata fields (a minimal "CI check")
- [ ] Commit the folder with clear commit messages per rule

## Tools

Git, a scripting language of your choice for the metadata check

## Deliverable

A `detections/` folder with rules-as-files, each with metadata, plus the metadata-check script.
